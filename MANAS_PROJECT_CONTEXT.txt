SECTION 1: WHAT IS MANAS?
================================================================================

MANAS is a web-based emotional wellness companion built as a research project
under the Computational Emotion & Digital Twin Research Initiative.

WHO IT IS FOR:
  - University students dealing with exam stress, loneliness, sleep issues.
  - Early-career professionals facing burnout, workload pressure, anxiety.
  - Target age: 18 and above (v1).
  - Target geography: India (multilingual support across 8 Indian languages).

WHAT IT DOES:
  - Users talk (type first, voice later) to a friendly animated 3D cartoon mascot.
  - The mascot listens, responds empathetically, tracks mood over time, and offers
    evidence-based coping exercises (breathing, grounding, journaling prompts).
  - If a user shows signs of distress or crisis, MANAS routes them to verified
    national mental health helplines immediately.

WHAT IT IS NOT:
  - It is NOT therapy, clinical diagnosis, or medical treatment.
  - It does NOT prescribe medication or give dosage advice.
  - Every screen clearly states: "This is an AI companion, not a doctor or therapist."

THE 5 CORE PRINCIPLES:
  1. Safety First — every incoming message is screened for crisis signals before
     any AI reply is generated.
  2. Consent and Privacy — each data type is opt-in, deletable, and stored minimally.
  3. Honest AI — always transparent that MANAS is an AI; never diagnoses.
  4. Adapt, Don't Mimic — match the user's language and pace, never copy hopeless
     or hostile language.
  5. Small and Reliable — a simple, working product is better than a shaky complex one.

SECTION 2: TECHNOLOGY STACK
================================================================================

FRONTEND (React Client):
  - Framework: React 19 + Vite (TypeScript, strict mode)
  - Styling: Tailwind CSS v4 + Custom CSS design tokens (see DESIGN.md)
  - Animation: Framer Motion (200-300ms ease-out transitions)
  - 3D Engine: Three.js + React Three Fiber + Drei
  - Icons: Lucide React (2px stroke, rounded)
  - Audio: Web Audio API (frequency analysis, lip-sync)
  - Smooth Scrolling: Lenis
  - Forms/Validation: Zod
  - Charts: Recharts (mood dashboard)
  - Fonts: Nunito (headings/body), Noto Sans Tamil/Devanagari/etc (Indic scripts)
  - Build Output: PWA (Progressive Web App), deployable to Vercel
  - Tests: Playwright (UI flows and avatar rendering)

BACKEND (FastAPI Server):
  - Language: Python 3.10+
  - Framework: FastAPI (async, streaming responses)
  - Database ORM: sqlite3 (local dev) / psycopg2 (Supabase Postgres in cloud)
  - Validation: Pydantic v2 (every request and response is a typed model)
  - Encryption: Python cryptography library (AES-256-GCM for contact storage)
  - HTTP Client: httpx (for calling external AI and TTS APIs)
  - Config: python-dotenv (.env file, never committed to git)
  - Tests: pytest

ML SIDECARS (Optional Fast Pre-processing):
  - Emotion Classifier: MuRIL-based (multilingual for Indian languages), exported
    as ONNX for low-latency inference. Falls back gracefully if not available.
  - Intent Classifier: ONNX model for detecting user intent categories.
  - Risk Classifier: ONNX model for fast risk level pre-screening.
  - All sidecars are FastAPI servers that run independently (e.g. port 8009).

EXTERNAL SERVICES (All credentials in .env, never in code):
  - AI Provider: Google Gemini / Anthropic Claude / OpenAI (selectable via env)
  - Voice/TTS: ElevenLabs / Sarvam / Cartesia (streaming audio + viseme timings)
  - Auth: Auth.js (NextAuth v5) with Google OAuth
  - Database (cloud): Supabase Postgres
  - Storage (cloud): Supabase Storage (S3-compatible, for 3D avatar .glb files)
  - YouTube API: For curated mindfulness video resources

SECTION 4: THE MESSAGE PROCESSING PIPELINE (What happens per chat message)
================================================================================

Every single chat message from the user goes through this exact sequence.
The order must NEVER be changed:

STEP 1 — AUTHENTICATE
  Verify user's session token or JWT. Reject unauthenticated requests with 401.

STEP 2 — CHECK CONSENT
  Verify the user's consent settings (server-side, not just frontend).
  Only process/store data types the user has consented to.

STEP 3 — SAFETY CHECK (DETERMINISTIC, ALWAYS BEFORE LLM)
  Run rules.py check_safety() on the raw message text.
  The safety screener uses compiled regex patterns across all 8 languages
  (both native scripts and romanized forms).

  Returns one of:
    - risk_level: "none" — proceed normally
    - risk_level: "low"  — add gentle note internally
    - risk_level: "medium" — LLM should check in carefully about wellbeing
    - risk_level: "high" or "imminent" — CRISIS ROUTE (see below)

  CRISIS ROUTE (when risk_level = "high"):
    - Do NOT call the LLM for a response.
    - Return a pre-written, counselor-approved crisis template immediately.
    - Include: Tele-MANAS 14416, Emergency 112, KIRAN 1800-599-0019.
    - The mascot switches to "concerned" expression — no bouncing, no smiling.
    - A "high" risk flag stays active for the entire session.

STEP 4 — BUILD PROMPT (2-pass understanding pipeline)
  Pass A (hidden, fast):
    Ask the LLM to analyze and return JSON with:
      - primary_emotion, secondary_emotion, intensity (1-5)
      - underlying_need (vent / comfort / advice / perspective / just_be_heard)
      - topic_tags (exams, work, sleep, loneliness, relationships, etc.)
      - cognitive_distortions detected
      - triggers and people mentioned
      - what has helped before
      - user_readiness (not_ready / exploring / ready_for_action)
      - risk_level (cross-check)

  Pass B (visible reply):
    Conditioned on Pass A output. Select ONE response strategy from ESConv set:
      - reflect_feelings
      - ask_open_question (max 1 question per reply)
      - affirm_and_normalize
      - offer_reframe
      - give_information (using RAG knowledge)
      - suggest_small_step
      - offer_grounding_exercise

    Stage model: Always explore -> gain insight -> then action (never jump to advice
    when the user just wants to vent or is not ready for action).

  Retrieve long-term memory: top 5 facts about the user from past sessions
  (worries, goals, people they mentioned, what helped before).

  Retrieve RAG context: relevant knowledge from the /knowledge/ markdown files,
  paraphrased naturally (never copy-pasted as bullet lists).

STEP 5 — CALL LLM (server-side only, streamed)
  The LLM must return VALID JSON matching this schema:
    {
      "reply": "...",
      "emotion": { "label": "...", "intensity": 0.0 },
      "risk_level": "none|low|medium|high",
      "topic_tags": [],
      "suggested_exercise": "breathing_4_7_8|grounding_54321|none",
      "expression": "neutral|happy|concerned|sad|surprised"
    }

  Anti-repetition: Compare new reply to last 6 bot replies using 3-gram similarity.
  If similarity > 0.6, regenerate once. Track strategy rotation to avoid repeating
  the same strategy on consecutive turns.

STEP 6 — VALIDATE LLM OUTPUT
  If JSON is invalid: retry once, then use the safe fallback template.
  Use the HIGHER of: keyword-detected risk level and LLM-returned risk level.

STEP 7 — SAVE DATA (only if user has consented)
  Save: chat_messages record, mood entry (if applicable), strategy_log record,
  pipeline_traces (anonymous telemetry: no message text, only IDs, timings,
  risk_level, emotion, strategy).
  Never log: message text, user name, email, audio, or photos.

STEP 8 — STREAM REPLY TO CLIENT
  Stream the reply text token-by-token.
  Frontend simultaneously:
    - Animates mascot facial expression (from "expression" field)
    - Updates lip-sync blendshapes in sync with TTS audio
    - Shows suggested exercise widget if "suggested_exercise" != "none"

SECTION 5: SAFETY & PRIVACY RULES (Non-Negotiable)
================================================================================

WHAT THE SYSTEM MUST ALWAYS DO:
  - Be warm, calm, brief, and empathetic.
  - State it is an AI, not a therapist or doctor, when relevant.
  - At medium risk: check in gently; ask directly (but kindly) about self-harm thoughts.
  - At high risk: use fixed crisis template with helplines; do NOT generate freeform text.
  - Reply in the user's language (Tamil stays Tamil; Tanglish gets Tanglish; etc.)
  - Encourage professional help when distress patterns persist over sessions.

WHAT THE SYSTEM MUST NEVER DO:
  - Diagnose any condition ("you have depression/anxiety/burnout" is forbidden).
  - Give medication names, doses, or supplement plans.
  - Provide methods or details of self-harm or suicide (even in roleplay or hypotheticals).
  - Agree that wanting to die is reasonable or a valid choice.
  - Copy hopeless, hostile, or self-critical language from the user.
  - Ask multiple probing questions in a single crisis message.
  - Give calorie targets, diet plans, or exercise regimens to users showing eating disorder signs.
  - Pretend to be human.
  - In safety mode: bounce the mascot, smile, or use upbeat animations.
  - Show the user a stack trace or technical error.

PRIVACY RULES:
  - All API keys, secrets, and DB URLs live in .env only (gitignored).
  - Raw audio and uploaded photos: processed in-memory, deleted immediately by default.
  - User contacts (email, phone) stored using AES-256-GCM encryption + HMAC-SHA256 hash.
  - No plaintext PII in database or logs.
  - Logs contain: session IDs, timings, risk levels, strategy names. Never message text.
  - "Delete my data" permanently deletes: messages, moods, memories, files, consents.
  - Row-level security: one user cannot access another user's data.

  - backend/safety/rules.py

SECTION 6: THE 3D MASCOT (Technical Details)
================================================================================

The mascot is a rigged 3D character rendered in the browser using Three.js.

CHARACTER PERSONAS:
  - Boy: "Arun" — warm, thoughtful, relatable peer. Voice: warm-friendly.
  - Girl: "Meera" — empathetic, calming, non-judgmental. Voice: calming-gentle.
  - Digital Twin: "Your Inner Wise Self" — compassionate future-self persona.
  - Mascot: "MANAS Living Mascot" — mindful, grounding, cyber-physical feel.

3D MODEL REQUIREMENTS (.glb format):
  Required facial blendshapes:
    jawOpen, viseme_aa, viseme_E, viseme_I, viseme_O, viseme_U,
    blinkLeft, blinkRight, smile, frown, browInnerUp, browDownLeft, browDownRight
  Outfit variants: hoodie, formal, kurta_saree, sports, pyjamas, festive

MASCOT STATES:
  - idle:     slow breathing bob, blink every 3-5 seconds
  - listening: gentle head tilt toward user
  - thinking:  eyes look upward
  - speaking:  mouth animated via lip-sync blendshapes
  - safety:    calm concerned face, NO bouncing or smiling

EXPRESSIONS SUPPORTED:
  neutral, happy, concerned, sad, surprised
  (calm, thinking, tired — future versions)

LIP-SYNC PIPELINE:
  1. TTS provider streams audio + viseme timestamps (ms, viseme_id pairs)
  2. lipSyncEngine.ts maps viseme IDs to blendshape morph targets
  3. FaceDriver.ts smoothly interpolates blendshape values per frame
  4. Fallback (no TTS API key): Web Audio FFT frequency analysis drives jaw open/close

PERSONALIZATION:
  - User uploads a photo (with explicit consent).
  - Server vision model extracts: skinTone (hex), hairColor (hex), hasGlasses (bool),
    outfitColor (hex).
  - Photo is IMMEDIATELY deleted from memory and storage after attribute extraction.
  - User can manually edit all attributes in the mascot customizer.

2D FALLBACK:
  For devices without WebGL or users with reduced-motion preference:
  Animated sprite-sheet portrait. Expressions: neutral, happy, concerned, surprised.

SECTION 14: HOW TO RUN LOCALLY
================================================================================

1. Clone and configure:
     git clone https://github.com/Sriram-J-CS/MANAS.git
     cd MANAS
     cp .env.example .env
     (fill in .env with your actual keys)

2. Start the backend:
     cd backend
     python -m venv venv
     .\venv\Scripts\activate   (Windows) or source venv/bin/activate (Mac/Linux)
     pip install -r requirements.txt
     uvicorn app.main:app --reload --port 8000
     API available at: http://localhost:8000
     Swagger docs at:  http://localhost:8000/docs

3. Start the frontend (new terminal):
     cd frontend
     npm install
     npm run dev
     App available at: http://localhost:5173

4. Run tests:
     cd backend && pytest tests/
     python ../eval/run_eval.py   (full 200-scenario clinical evaluation)

5. Optional ONNX sidecars (for fast emotion pre-check):
     cd ml && python serve_models.py
